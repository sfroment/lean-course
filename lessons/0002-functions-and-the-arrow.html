Lesson 0002 · Phase A — Foundations

Functions and the arrow →

Builds on Lesson 0001. 20–30 minutes.

The one idea

In Lean, P → Q (logical implication) is the same arrow as a function type Nat → Nat. There is only one arrow. That single fact unifies "functions" and "proofs of implications" — and it's why Lean can check both with one kernel.

1. Defining a function: def

def double (n : Nat) : Nat := n + n

#check double        -- double : Nat → Nat
#check double 21     -- double 21 : Nat
#eval double 21      -- 42

def name (args) : ReturnType := body defines a named function. Application is just juxtaposition: double 21, no parentheses needed.

2. Anonymous functions: fun

example : (fun x : Nat => x + 1) 5 = 6 := rfl
example : (fun (x y : Nat) => x + y) 2 3 = 5 := rfl

fun x => body is a function literal (like a lambda). Multi-argument: fun (x y : Nat) => x + y.

3. Functions are values

def add (a b : Nat) : Nat := a + b
example : add 2 3 = 5 := rfl

Functions have types (add : Nat → Nat → Nat — the arrow associates to the right), can be passed around, and are checked like any other term. A proof that add 2 3 = 5 is still just rfl, because both sides compute to the same number.

4. Try it yourself

In playground/, create MyScratch.lean and write:

def square (n : Nat) : Nat := n * n
example : square 3 = 9 := rfl

Check with cd playground && lake env lean MyScratch.lean. Then try def compose (f g : Nat → Nat) (x : Nat) : Nat := f (g x) and #eval compose double double 5. Or use the ✏️ Pencil scratchpad to write the code by hand first.
